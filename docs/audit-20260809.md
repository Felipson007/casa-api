## Findings

### F-1 (D-012) — `member_permissions` is empty in seed, and has no source in the Java prod DB
- `000001` defines `member_permissions (user_id, module, can_read, can_write)` — our single-tenant authz store (D-003).
- The Java prod DB has **no** `member_permissions`; permissions lived in `tenant_members` (per-tenant, boolean columns `permite_clientes_leitura/escrita`, `permite_emprestimos_*`, `permite_saude_*`, ...).
- ETL never emits `member_permissions` rows → seed has it **empty** → every MEMBER is denied everywhere (only OWNER works, via the RequirePerm OWNER-bypass we added).
- Impact: cannot end-to-end test the "MEMBER allowed" path from seed.
- Proposal (D-012, PROPOSED): add one `member_permissions` row for the demo MEMBER (`sanches57@uni9.edu.br`) granting e.g. `expenses` read+write, injected in `build-seed.sh` post-ETL (not hand-edited into `seed.sql`, which is regenerated). Awaiting Claude's agreement.

### F-2 — `movimentacoes` (Java) IS correctly mapped by `loan_transactions` (000001) — NO schema gap
- Java `movimentacoes`: `{id, tenant_id, cliente_id, emprestimo_id, parcela_id, tipo, valor, data_pagamento, descricao, origem_legado}`.
- `000001` `loan_transactions`: `{id, client_id, loan_id, installment_id, type, amount, payment_date, description, legacy_source, created_at}` — **field-for-field equivalent**, just English names.
- Enum mapping is 1:1 and CORRECT: `TipoMovimentacao` (DESEMBOLSO, RECEBIMENTO_PARCELA, RECEBIMENTO_AVULSO, PERDAO, AMORTIZACAO) → `loan_transactions.type` CHECK (DISBURSEMENT, INSTALLMENT_PAYMENT, ONE_OFF_PAYMENT, FORGIVENESS, AMORTIZATION).
- **Correction to earlier audit note:** there is NO schema mismatch — `loan_transactions` already *is* the `movimentacoes` ledger. The only missing piece is the **generation logic** (loans part-2): when a parcela is paid → insert INSTALLMENT_PAYMENT; on disbursement → DISBURSEMENT; ad-hoc payment → ONE_OFF_PAYMENT; forgiveness → FORGIVENESS; principal amortization → AMORTIZATION (and AMORTIZATION also reduces `outstanding_balance` via `EmprestimoRecorrenteService.aplicarAmortizacao`). That logic belongs in `internal/loans` part-2 (Claude-owned). No migration change needed.
